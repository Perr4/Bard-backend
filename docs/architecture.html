BARD Backend — Architettura

Flusso delle informazioni tra client, gateway, microservizi, Eureka e PostgreSQL

Ingresso unico

  • • api-gateway su :8080, WebFlux reattivo
  • • valida il Bearer JWT con chiave HMAC
  • • instrada con lb:// verso il servizio
  • • gestisce CORS per il frontend

Service discovery

  • • eureka-service su :8761
  • • i servizi si registrano all'avvio
  • • il gateway risolve il nome → istanza
  • • nessun indirizzo fisso nel codice

Dati condivisi

  • • un solo PostgreSQL, schema bard
  • • auth_users · auth_roles · auth_user_roles
  • • ballerini · presenza
  • • ddl-auto: none / update / validate

Composizione del ballerino

  • • ballerini-service → auth-service
  • • GET /api/auth/internal/users/{id}
  • • restituisce nome, cognome, dataNascita
  • • una chiamata per ballerino (N+1)
